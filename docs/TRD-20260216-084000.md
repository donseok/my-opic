## 1. 기술 요약 (Executive Summary)

OPIc Master는 OPIc 시험 대비 개인 학습 웹 앱으로, 클라이언트 사이드 중심의 SPA(Single Page Application) 아키텍처를 채택한다. PRD에서 정의된 기술 스택 제약(HTML/CSS/JavaScript, SQLite, Gemini API)에 따라 프레임워크 없는 순수 Vanilla JS 기반으로 개발하며, 백엔드는 Node.js Express로 최소한의 API 프록시와 SQLite 데이터 접근 계층을 제공한다.

핵심 기술 결정은 다음 세 가지이다. 첫째, 3시간 MVP 제약에 최적화된 단순 아키텍처를 채택하여 모놀리식 구조로 프론트엔드와 백엔드를 단일 프로젝트에 구성한다. 둘째, Gemini API Key 보안을 위해 Node.js 백엔드를 경유하는 프록시 패턴을 적용하여 클라이언트 사이드에 API Key가 노출되지 않도록 한다. 셋째, SQLite 파일 기반 로컬 저장소를 사용하여 별도 DB 서버 없이 단일 파일로 모든 데이터를 관리한다.

UI는 Google Stitch에서 생성한 HTML/CSS를 기반으로 다크 모드 테마(배경 #0F172A, 카드 #1E293B, 액센트 #2DD4BF)를 적용하며, SVG 기반 원형 타이머와 Chart.js 라인 차트로 시각화 요소를 구현한다. 전체 시스템은 로컬 환경에서 `npm start` 한 번으로 실행 가능한 단순한 구조를 목표로 한다.

**아키텍처 스타일**: 모놀리식 (Monolithic) — 3시간 MVP 제약에 최적화

```
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └─────┬─────┘  │
│       │             │            │              │        │
│  ┌────┴─────────────┴────────────┴──────────────┴────┐  │
│  │              Navigation (Tab Bar)                  │  │
│  └────────────────────┬──────────────────────────────┘  │

                        │ HTTP (fetch API)

│  │              API Router (/api/v1)                  │  │

│  │ Topics   │ Levels   │  Exam    │  Feedback       │  │
│  │ API      │ API      │  API     │  API (Proxy)    │  │
│  └────┬─────┘└────┬────┘└────┬────┘└───────┬────────┘  │
│       │           │          │             │            │

```

### 3.2 계층별 설명
| 계층 | 설명 | 핵심 컴포넌트 |
|------|------|-------------|
| Presentation Layer | HTML/CSS/JS 기반 SPA. Stitch 디자인 적용. 다크 모드 테마 | 6개 화면 모듈 (Survey, Level, QuestionBank, Exam, Feedback, Dashboard), Navigation TabBar |
| API Layer | Express.js REST API. 프론트엔드 요청 처리 및 Gemini API 프록시 | TopicsRouter, LevelsRouter, ExamRouter, FeedbackRouter, SettingsRouter |
| Data Access Layer | better-sqlite3 기반 데이터 접근. 트랜잭션 지원 | Database 싱글턴, 테이블별 Repository 모듈 |
| External Integration | Gemini API 호출. API Key 보안 관리 | GeminiService (프롬프트 구성, 응답 파싱, 에러 처리) |

### 3.3 데이터 흐름

**모의시험 → AI 피드백 흐름 (핵심 시나리오):**

```
[사용자] → 시험 시작 클릭
    → [Exam Module] → GET /api/v1/exam/questions (5문제 요청)
    → [Express] → SQLite 쿼리 (선택 주제 기반 랜덤 5문제)
    → [사용자] ← 5문제 수신, 타이머 시작

[사용자] → 5문제 답변 완료
    → [Exam Module] → POST /api/v1/exam/sessions (답변 저장)
    → [Express] → SQLite INSERT (exam_sessions + exam_answers)

[사용자] → AI 피드백 요청 클릭
    → [Feedback Module] → POST /api/v1/feedback/evaluate
    → [Express/GeminiService] → Gemini API 호출 (시스템 프롬프트 + 답변 데이터)
    → [Gemini API] → JSON 응답 (등급, 점수, 피드백)
    → [Express] → 응답 파싱 → SQLite INSERT (ai_feedbacks) → 클라이언트 응답
    → [사용자] ← 피드백 시각화 (등급 뱃지, 점수 게이지, 피드백 카드)
```

### 3.4 배포 다이어그램

**로컬 실행 환경 (MVP):**

```
[로컬 PC]
├── Node.js Express Server (localhost:3000)
│   ├── Static Files (public/)     ← HTML/CSS/JS
│   ├── API Endpoints (/api/v1/)   ← REST API
│   └── opic_master.db             ← SQLite 파일
├── .env                           ← GEMINI_API_KEY
└── Chrome Browser                 ← http://localhost:3000
```

실행 명령어: `npm start` → Express 서버가 정적 파일 서빙 + API 제공

## 10. 기술 리스크 (Technical Risks)

| ID | 리스크 | 영향도 | 대응 방안 | 대안 (Contingency) |
|----|--------|--------|----------|-------------------|
| TR-001 | Gemini API 무료 티어 한도 초과 (15 RPM, 1,000 RPD) | HIGH | 요청 횟수를 카운트하고, 한도 근접 시 사용자에게 경고 표시 | 하루 사용 횟수를 UI에서 제한 (최대 10회/일 권장) |
| TR-002 | Gemini API 응답 형식이 기대와 다름 (JSON 파싱 실패) | MEDIUM | 응답 검증 로직 추가. JSON 파싱 실패 시 재시도 (temperature 조절) | 기본 피드백 템플릿으로 폴백하고 원본 응답을 raw_response에 저장 |
| TR-003 | 3시간 내 MVP 완성 실패 | HIGH | P1 기능을 마일스톤 순서대로 구현하여 부분 완성이라도 동작하도록 설계 | M1(설정)만 완성해도 앱 구조 이해 가능, M2(시험)까지 완성이 최소 목표 |
| TR-004 | Google Stitch 생성 HTML/CSS와 기능 코드 통합 충돌 | MEDIUM | Stitch 출력물을 컴포넌트 단위로 분리하여 레이아웃만 참조 | Stitch 없이 직접 CSS 작성 (디자인 가이드 색상 코드 활용) |
| TR-005 | SQLite 동시 접근 문제 (브라우저 여러 탭 열기) | LOW | 단일 사용자 앱이므로 WAL 모드 활성화로 충분 | 동시 접근 감지 시 경고 메시지 표시 |
| TR-006 | 네트워크 불안정으로 Gemini API 호출 실패 | MEDIUM | 15초 타임아웃 + 재시도 버튼 제공 (FR-026) | 오프라인 모드에서 시험까지만 가능하도록 안내 |
| TR-007 | 비개발자 수강생의 환경 설정 실패 (Node.js, npm, API Key) | MEDIUM | 단계별 설정 가이드 README 제공. npm install && npm start 원클릭 실행 | 강사가 사전 설정된 환경을 USB/클라우드로 배포 |
